### 4. 固定音频位置

```text
outputs/assets/audio/v2.1/en-GB-SoniaNeural/
  manifest.json
  word-*.mp3
  training-*.mp3
  acceptance-*.mp3
  story-*.mp3
```

音频 ID 的生成规则：

```text
SHA-256(kind + NUL + 规范化文本) 的前 16 个十六进制字符
文件名 = kind + "-" + ID + ".mp3"
```

页面通过 `manifest.json` 按“音频类型 + 文本”查找 MP3，不依赖词条序号。

音频类型固定为：

```text

training   语境训练句
acceptance 验收句
story      故事朗读
```

## 三、完整制作流程

### 第 0 步：确认环境和范围

开始前先确认：

1. 当前工作区是否干净。
2. Python 和 Node.js 是否可用。
3. 是否保留 `work/audio-tools/vendor` 中的微软语音组件。
4. 本次是做新单元、修改旧单元，还是只更新音频。
5. 用户附件中的 Excel 路径和工作表名称。

推荐检查命令：

```powershell
git status --short --branch
python --version
node --version
Test-Path "work\audio-tools\vendor\edge_tts"
```

### 第 1 步：只核对词汇，不先写页面

从 Excel 读取词汇总表和重点词汇表，先输出明确结论：

```text
单元：
全部词条数：
重点词条数：
词条来源工作表：
是否包含短语：
是否包含缩写：
是否包含专有名词：
输出版本：全部 / 重点 / 两者都做
```

处理规则：

- 严格保留教材顺序。
- 不凭教材印象补词、删词或替换词。
- 全部词条版必须覆盖词表全部内容。
- 重点词汇版只保留表格星标或重点工作表中的词。
- 英文大小写、空格、连字符和缩写保持教材写法。
- 中文释义可以适度精简，但不能改变原意。

### 第 2 步：建立词汇数据结构

每个词条至少包含：

```json
{
  "en": "biology",
  "zh": "生物学",
  "ipa": "/baɪˈɒlədʒi/",
  "pos": "n.",
  "group": "subjects"
}
```

字段说明：

- `en`：教材英文词条。
- `zh`：中文释义。
- `ipa`：音标，可为 `-`。
- `pos`：词性。
- `group`：干扰项分组。

完成数据后必须先自动核对：

```text
实际词条数 = 表格词条数
重点词条数 = 表格星标词条数
英文词条无重复
词条顺序与表格一致
```

### 第 3 步：生成训练句、验收句和故事

每个词条必须有一套语境数据：

```json
{
  "sceneId": 1,
  "trainingSentence": "Mr. Li teaches {{word}} in the science lab.",
  "trainingZh": "李老师在科学实验室教生物学。",
  "acceptanceSentence": "We learn about plants and animals in {{word}}.",
  "acceptanceZh": "我们在生物学课上学习植物和动物。"
}
```

硬性规则：

- 每条英文训练句恰好有一个 `{{word}}`。
- 每条英文验收句恰好有一个 `{{word}}`。
- 中文验收句恰好有一个 `{{word}}`。
- 训练句和验收句不能相同。
- 验收句要使用新的语境。
- 句子应能明确判断目标词，不能同时适合多个选项。
- 每个词条只能归入四幕故事中的一幕。
- 四幕故事必须恰好覆盖当前版本的全部词条，不遗漏、不重复。
- 句子优先使用校园、家庭、学习、运动和日常生活场景。

### 第 4 步：扩展或生成页面

页面基础模板：

```text
outputs/v2.1/index.html
```

普通单元构建脚本示例：

```text

work/v21-unit3/build_unit3.py

work/v21-unit5/build_unit5.py
work/v21-unit6/build_unit6.py

```

生成或更新时检查以下动态数据：

```text
WORDS
CONTEXT_SCENES
CONTEXTS
STAGES
CONTEXT_ACCEPTANCE_STAGES
```

页面中不能残留旧单元的固定数字，例如：

```text
20 个单词
80 / 80
/20
当前 80 格训练进度
 masteredThisRound = 20
 masteredThisScene = 5
```

全部生成命令：

```powershell

```

### 第 5 步：使用电脑端工具生成固定音频

工具位置：

```text
tools/audio-downloader/启动音频下载工具.cmd
```

使用方法：

1. 双击启动脚本。
2. 浏览器打开本地工具。
3. 选择微软英文音色。
4. 点击“试听当前音色”。
5. 勾选词条、训练句、验收句和故事。
6. 点击“开始批量生成”。
7. 完成后点击“下载全部 ZIP”或逐条下载。

默认端口：

```text
http://127.0.0.1:8865/
```

如果端口被占用，工具会自动尝试 8866、8867 等后续空闲端口。实际地址以黑色命令窗口显示为准。

输出目录：

```text
tools/audio-downloader/downloads/<Microsoft voice id>/
```

需要上传网站时，复制到：

```text
outputs/assets/audio/v2.1/<Microsoft voice id>/
```

当前 Sonia 音频：

```text
tools/audio-downloader/downloads/en-GB-SoniaNeural/
outputs/assets/audio/v2.1/en-GB-SoniaNeural/
```

### 第 6 步：接入固定音频

页面模板中必须保留以下配置：

```javascript
const AUDIO_BASE = '../assets/audio/v2.1/en-GB-SoniaNeural/';
const AUDIO_MANIFEST_URL =
  '../assets/audio/v2.1/en-GB-SoniaNeural/manifest.json';
const FIXED_AUDIO_ENABLED = true;
```

播放规则：

- 页面加载后预取 `manifest.json`。
- 所有朗读共用一个 `narrationPlayer`。
- 音频类型必须与清单一致：`word`、`training`、`acceptance`、`story`。
- 学生点击“开始训练”时播放一次静音音频，解锁微信内置浏览器播放器。
- 解锁后，后续题目使用同一个播放器自动朗读。
- 自动播放失败时，保留手动喇叭按钮，提示学生点击重听。

苹果微信的技术限制：

```text
页面在用户第一次点击之前不能保证自动发声。
因此首次点击“开始全覆盖训练”是必要的用户手势。
之后通过同一个音频播放器解锁自动播放。
```

## 七、常见问题与处理

### 1. 页面没有声音，但手动点击可以

先区分：

```text
设备语音问题 -> speechSynthesis
固定 MP3 问题 -> manifest、路径、HTMLAudio 或自动播放策略
```

当前版本应使用固定 MP3，不应依赖设备语音。

### 2. 苹果微信第一次进入题目不自动播放

这是浏览器安全限制。正确方案：

1. 学生点击“开始全覆盖训练”。
2. 在本次点击中播放一次静音 WAV。
3. 后续题目复用同一个 `narrationPlayer` 自动播放。

不能保证在完全没有点击的情况下自动播放。

### 3. 只有语境训练没声音

检查音频类型是否一致：

```text
页面：training
manifest：training
```

不能一边写 `train`，另一边写 `training`。

### 4. 只有验收题没声音

检查：

```text
页面：acceptance
manifest：acceptance
```

不能一边写 `accept`，另一边写 `acceptance`。

### 5. 本地音频工具启动失败

检查：

- 是否双击 `启动音频下载工具.cmd`。
- Python 是否安装。
- 命令脚本是否保持 Windows CRLF 换行。
- 端口是否被占用。

当前默认端口为 8865，被占用后会自动顺延。

### 6. GitHub 音频上传后 404

检查：

- 音频是否放在 `outputs/assets/audio/v2.1/en-GB-SoniaNeural/`。
- `pages.yml` 是否复制该目录。
- manifest 中的文件名是否与实际文件一致。
- Actions 是否成功完成。

### 7. 选项不足 4 个

先取同组干扰项，再从其他组补齐，最终始终生成 3 个干扰项。

### 8. 两个版本进度互相覆盖

必须使用不同的 `PROGRESS_KEY`：

```text
word-planet-unit-4-v2.1-unit4-progress-v3
word-planet-unit-4-v2.1-unit4-key-progress-v3
```
