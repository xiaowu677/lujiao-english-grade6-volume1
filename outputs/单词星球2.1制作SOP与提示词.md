# 单词星球 2.1 完整制作 SOP 与提示词

本文档用于复用当前工作区中的“单词星球 2.1”制作方式。下一次制作新单元时，可以直接复制文中的提示词，并把单元号、词条范围和附件路径替换掉。

## 一、成品标准

每次制作开始时，先确认以下信息：

| 项目 | 默认标准 |
| --- | --- |
| 视觉风格 | 沿用 `outputs/v2.1/index.html` 的深色星球界面 |
| 基础训练 | 每个词条 4 种模式，每种答对一次 |
| 语境训练 | 四幕故事，每个词条至少进入一个故事场景 |
| 最终验收 | 每个词条 1 题，使用与训练句不同的新语境 |
| 通关标准 | 首轮正确率达到 90%，错词完成订正 |
| 输出形式 | 单个可独立打开的 HTML 文件 |
| 页面尺寸 | 桌面端和手机端均可使用 |
| 进度保存 | 按单元和版本使用独立浏览器存储键 |

本次 Unit 4 的实际基准：

| 版本 | 词条数 | 基础训练格 | 语境训练 | 最终验收 |
| --- | ---: | ---: | ---: | ---: |
| 全部词条 | 35 | 140 | 35 | 35 |
| 重点词汇 | 22 | 88 | 22 | 22 |

## 二、完整制作流程

### 第 1 步：确认范围，不先写页面

先从附件中读取词汇表，并确认：

1. 目标单元一共有多少条。
2. 其中有多少条带星标或属于重点词汇。
3. 是否包含短语、缩写、专有名词。
4. 用户要做“全部词条”还是“重点词汇”，或者两个版本都要。
5. 中文释义过长时是否允许精简，但不能改变原意。

建议在开始前把范围写成明确结论，例如：

> Unit 4 共 35 条，其中 22 条重点词汇。制作全部 35 条版和重点 22 条版。

不要凭单元号猜测数量，也不要在没有核对表格的情况下手写词条。

### 第 2 步：建立词汇数据

从 Excel 的“词汇总表”或“重点词汇”工作表读取数据，并保留教材原顺序。

每个词条至少整理成以下结构：

```json
{
  "en": "biology",
  "zh": "生物学",
  "ipa": "/baɪˈɒlədʒi/",
  "pos": "n.",
  "group": "subjects"
}
```

数据处理规则：

- `en` 使用教材写法，包括大小写和空格。
- `zh` 可以精简为适合选项按钮的长度，但含义必须准确。
- `ipa` 和 `pos` 保留用于后续展示或扩展。
- `group` 用来优先选择同类干扰项；同类不足时，从其他词条补齐。
- 不擅自删除短语、缩写、专有名词，除非用户明确只做重点词汇。
- 两个版本的词条顺序分别保持与对应表格一致。

完成后先做一次自动核对：

```text
全部词条数 = Excel 单元总词条数
重点词条数 = Excel 星标词条数
英文词条无重复
输出顺序与教材顺序一致
```

### 第 3 步：补全语境内容

每个词条都需要以下内容：

```json
{
  "sceneId": 1,
  "trainingSentence": "Mr. Li teaches {{word}} in the science lab.",
  "trainingZh": "李老师在科学实验室教生物学。",
  "acceptanceSentence": "We learn about plants and animals in {{word}}.",
  "acceptanceZh": "我们在生物学课上学习植物和动物。"
}
```

内容规则：

- 英文训练句和验收句都必须恰好有一个 `{{word}}`。
- 验收句不能直接复用训练句。
- 句子要能明显判断目标词，不能同时适合多个选项。
- 中文验收句必须保留一个 `{{word}}`，供“看中文语境选英文”使用。
- 优先使用校园、学习、生活等孩子容易理解的场景。
- 短语要尽量在自然语境中展示。
- 对 `help sb with` 这类教材句型，可以使用“这个短语表示……”的教学型句子，但中英文信息必须一致。
- 每个词条只归入一个故事场景；四幕故事合起来必须恰好覆盖当前版本的全部词条。

### 第 4 步：接入 2.1 页面

沿用现有页面结构，只替换数据和必要的动态逻辑：

1. 替换 `WORDS`。
2. 替换 `CONTEXT_SCENES`。
3. 替换 `CONTEXTS`。
4. 按实际词条数重新生成 `STAGES` 和 `CONTEXT_ACCEPTANCE_STAGES`。
5. 所有页面总数、进度、里程碑、验收和成绩单数字改为动态值。
6. 每个版本使用独立的 `localStorage` 键，避免两个版本互相覆盖进度。
7. 选项永远保持 4 个；同类词不足时从其他分组补齐。

建议重点检查以下位置：

```text
首页：词条数、训练格数、语境题数、星球标签
训练页：当前掌握数、进度条、题目总数
故事页：四幕数量、本幕词条高亮
里程碑：本关词条数、剩余训练格
验收页：当前题号、总题数
成绩单：答题数、词条覆盖、模式覆盖、语境覆盖
```

### 第 5 步：运行数据和逻辑测试

至少验证：

- 全部词条数正确。
- 重点词条筛选正确。
- 词条顺序正确。
- 每个词条恰好有一个训练句和验收句。
- 每个词条恰好出现在一个故事场景。
- 每道题恰好有 1 个正确答案和 4 个选项。
- 基础训练总格数等于“词条数 × 4”。
- 最终验收总题数等于词条数。
- 页面文案中的总数与实际数据一致。
- 两个版本的存储键不同。

当前工作区的 Unit 4 可复用命令：

```powershell
python "work\v21-unit4\build_unit4.py"
node --test "work\v21-unit4\test_unit4.js"
```

### 第 6 步：真实浏览器验收

不能只看静态代码，至少要打开页面完成：

1. 点击“开始全覆盖训练”。
2. 确认题目、4 个选项和总题数正常。
3. 确认答对后自动进入下一题。
4. 抽查长单词、长短语和专有名词是否溢出。
5. 确认四幕故事能正常显示并高亮目标词。
6. 确认最终验收和成绩单能生成。
7. 在约 430px 手机宽度下确认没有横向溢出。
8. 检查控制台没有运行时错误。

## 六、常见问题

### 1. 只换单词，页面仍显示 20 个单词、80 格训练

原因是只替换了 `WORDS`，没有替换动态统计和固定文案。需要全局搜索并清除旧数字，再检查：

```text
20 个单词
80 格
20 / 20
80 / 80
/20
const masteredThisRound = 20
const masteredThisScene = 5
```

### 2. 选项不足 4 个

如果同类词太少，原逻辑只会从同类词中取干扰项。改为：

```text
先随机取同类干扰项，再从其他组补齐，总共取 3 个干扰项。
```

### 3. 两个版本共用进度

不要共用同一 `PROGRESS_KEY`。至少区分：

```text
word-planet-unit-4-full-progress-v3
word-planet-unit-4-key-progress-v3
```

### 4. 中文语境填空不显示

检查 `acceptanceZh` 是否保留了 `{{word}}`。如果中文句中直接写成了词义本身，页面就没有可替换的位置。

### 5. 手机页面文字被裁切

检查：

- 标题或标签是否用了不换行的白空间；
- 长短语、表格和多列网格是否设置了最小宽度；
- 页面 `scrollWidth` 是否大于视口宽度；
- 截图必须使用真实手机宽度，而不是缩小桌面截图。

### 6. 浏览器语音没有声音

2.1 当前版本主要使用浏览器设备语音，不包含独立 MP3 词库。需要确认：

- 浏览器是否支持 `speechSynthesis`；
- 用户是否已经点击过页面以解除自动播放限制；
- 系统是否安装了对应英语语音；
- 页面是否处于静音或受限环境。
